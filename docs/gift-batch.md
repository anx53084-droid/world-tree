# 团购礼品卡（Group Gift Cards）

路由：`#/gift/batch`（创建）· `#/gift/batch/<id>`（进度）· `#/claim/<code>`（领取）。代码：`batch.js`（队列/分片/领取码/领取）、`server.js`（`/api/batch/*`、`/api/admin/batch*`）、`public/app.js`（三个页面）。

## 1. 费用与资金规则（页面、进度页、领取页、本文一致）

- **平台收费**：每张最低 **1 美元等值**，由**创建者一次性支付**；总额 = 数量 × max(1, 单张平台费 USD)。币种仅 **SOL / ETH / BNB**（沿用现有多链支付与按链收款地址 `receive-config.js`）。**客户领取支付 0**。
- 平台费**全额直达项目收款地址**，本站不托管、不代持；不可转让、不可退款；仅用于项目运行成本、正向内容生态（树洞、门卡空间等）维护，以及提前公告的公益或社区用途。
- **卡片价值（USD，≥ 1）仅作记录**，写入批次/卡片元数据：平台不收取、不保管、不托管，也**不负责兑现**。创建者必须填写「兑换说明」（必填，≤ 200 字，过 `blocklist.js` 与承诺字样过滤）；领取页、进度页、我的门卡都显示卡片价值与兑换说明，并固定提示：「平台不保管资金、不负责兑现，请向创建者核实。」
- 不承诺任何回报：不提供收益、分红、投资回报、空投或增值预期；卡片价值不是投资品。服务端会拒绝含此类承诺字样的祝福/兑换说明/门卡名。
- 批量与单张规则相同；领取码一码一领、绑定领取账户、不可转让。
- 内容只做基础的长度与关键词自动过滤（`blocklist.js` + 现有正向内容审核），无人工审核。
- 页面底部固定声明（16 种语言）：「平台费直达项目地址，仅用于项目运行与正向生态建设；卡片价值仅作记录，平台不保管资金、不负责兑现，无收益承诺。」

### 费用示例

100 张 × 卡片价值 50 USD：创建者支付 **100 × max(1, 1) = 100 USD**（按报价折算成 SOL / ETH / BNB，例如 SOL = 150 USD 时 ≈ 0.666667 SOL）；卡片总价值 **5000 USD 仅作记录**，平台不收取、不保管、不兑现。若把单张平台费设为 2 USD，则付 200 USD，卡片价值仍只是记录。

### 网络费用（gas）——如实说明

- **平台不替任何人发交易**。网络费用由发起交易的钱包自行支付：创建者支付平台费的那一笔交易、可选的「门内记录上链」交易，都由创建者自己的钱包签名并支付 gas；托管（邮箱）账户则由该账户在服务端的密钥发起交易并承担网络费用（来自账户自身余额）。
- 客户领取是站内操作（校验码并绑定账户），**不需要链上交易，也不产生网络费用**；仅此而已，不存在“平台承担 gas”或“gas 已包含在平台费里”。页面与 16 种语言文案均按此说明。

## 2. 流程

1. 创建页：祝福（≤140）、数量（1–10000）、卡片价值（USD，≥1，仅记录）、兑换说明（必填 ≤200）、单张平台费（USD，≥1，默认 1）、币种（SOL/ETH/BNB）、门卡名称（≤20 字）、可选项；页面实时显示卡片价值、总价值、平台费 USD 及币种数量、本次需支付，并提示「每张最低 1 美元等值：约 x SOL / y ETH / z BNB」。
2. **价格**：`GET /api/prices`（公开）返回 SOL/ETH/BNB 的 USD 价（`prices.js`：Coinbase / Binance(data-api.binance.vision) / CoinGecko 多源取**中位数**，缓存 60 秒；全部失败时回退最近一次成功值并标记 `stale`）。前端只读该接口，不直连第三方。
3. **锁价报价**：提交时先 `POST /api/batch/quote {count,coin,feeUsd}`，服务端用当前价生成**签名报价令牌**（HMAC，绑定账户/币种/数量/单价/价格/过期时间，默认 10 分钟，`BATCH_QUOTE_TTL`）。该币没有 15 分钟内的真实报价（只有缓存回退值或兜底常量）时拒绝报价（`price`），避免按过期价格收费。
4. **一次支付**（金额 = 报价应付额）：
   - 自有 Solana 钱包（SOL）：客户端签**一笔**转账。勾选「公开 1 张」时同一笔交易带上经审核签名的心愿 memo 与 0-lamport TREE 转账；否则 memo 为 `WTREE1|BG|pay`。
   - 托管（邮箱）账户（仅 SOL）：服务端按锁价代签（≥ 20 USD 的大额需改用自有钱包）。
   - EVM 账户（ETH：Base/Sepolia/Arbitrum/Unichain；BNB：BSC）：沿用 `evmPay`，按链收款地址；不支持「公开 / 上链」选项。
5. 服务端核验：交易成功、**签名者 = 当前登录账户**、收款方 = 当前或遗留收款地址、到账 ≥ **锁价应付额的 98%**（2% 滑点容差；一律使用**服务端锁定价格**，前端传来的价格/金额不被信任）；币种与支付方式必须匹配；`paid[支付签名]` 防重放；同一支付签名不能同时用于广告与团购。篡改单价/数量/币种、伪造或他人的报价令牌、过期报价均被拒绝。
6. 通过后创建批次（所有者 = 登录钱包）写入任务队列，页面自动跳转进度页。

## 2.1 附加内容（图片 + 商品链接，可选，合计 ≤ 20）

- **位置**：创建页「兑换说明」下方；顶部实时计数「已添加 n/20」；按钮「添加图片」「添加商品链接」；列表项＝缩略图 + 名称/域名 + 操作（▲上移 ▼下移 ✕删除；鼠标可拖拽手柄排序，键盘与手机触摸用上移/下移按钮；商品链接标题可直接编辑；上传失败可重试或移除）。满 20 个时两个按钮置灰并提示「已达上限」。「预览领取页」按钮在表单内实时渲染领取页效果（含兑换说明、附加内容、免责声明）。草稿保存在浏览器 localStorage（`wt_gbdraft`：表单 + 附加内容元数据，创建成功后清除）。
- **完全可选、创建后不可修改**：不加附加内容时流程与之前完全一致；同一批次所有领取码看到的内容一致（存在批次上，不复制进每张卡）。
- **添加图片**：多选（不超过剩余数量）→ 浏览器内压缩（最长边 ≤ 1200px，质量 80%，< 2MB，WebP 优先，不支持则 JPEG）→ 上传到现有 `POST /api/img`（加 `att:true`：放宽到 ≤ 1200px / < 2MB，其余沿用类型 / 魔数 / NSFW 审核；普通上传仍是 1024px / 300KB）→ 存入平台图片存储（R2 或磁盘）。
- **添加商品链接**：弹窗填 URL（必填，http/https）、标题（选填 ≤ 60 字）、封面（选填，可上传）。「获取预览」调用 `POST /api/batch/link-preview`（登录，20 次 / 10 分钟 / 用户）：复用商品预览的 SSRF 防护抓取（仅 https、拒绝内网 / 回环 / 链路本地 / 元数据地址、DNS 校验后按 IP 连接防 rebinding、≤ 3 次重定向逐跳复查、8 秒超时、HTML ≤ 1.5MB / 图片 ≤ 5MB），取 `title` / `og:image`；封面转存为平台图片（同样过 NSFW 审核）后再使用，**绝不直接外链**。失败时用占位图 + 用户填的标题。**http 链接不抓取**（明文）。商品链接过 `blocklist.js`（短链 / 钓鱼 / 地址），标题过审核与承诺字样过滤；**不审核商品是否可用**。
- **服务端强制校验**（`batch.js normAtt` + `/api/batch/create`）：
  - 数组 ≤ 20 → 否则 `attMax`；类型只能是 `image` / `product` → 否则 `att`。
  - 图片 URL 只接受平台图片存储地址：`/api/img/<32 位哈希>`、平台域名（本机 host / 已登记域名）下的同路径绝对地址、或 `R2_PUBLIC_URL/<哈希>`；统一规范化为 `/api/img/<哈希>`，且该哈希必须真实存在于平台存储（即已通过上传审核）→ 否则 `attImg`（外链、其他域名、data: 一律拒绝）。
  - 商品链接：http/https、≤ 500 字、不带账号密码、主机名必须含点且不是 IP / localhost / `.local` / `.internal` 等 → 否则 `attLink`；封面必须是平台图片。
  - 链接与标题过 blocklist（`blocked`）、审核（`reject`）、承诺字样（`promise`）。
- **数据模型**：批次新增 `attachments: [{type:'image'|'product', url, title, cover, sort}]`（`sort` 从 0 按提交顺序）。旧批次没有该字段：领取页 / 进度页 / 门卡列表按“无附加内容”处理，模块不显示。
- **领取页**：兑换说明下方、免责声明上方显示「附加内容」（无内容不显示）；手机 2 列网格 / 桌面 3 列；图片 `loading=lazy`，点击全屏预览（站内对话框：焦点陷阱、Esc 关闭、左右按钮 / 方向键 / 触摸滑动切换）；商品链接显示封面 + 标题 +「查看商品」，点击先弹站内外链确认（沿用 `extLink`：钓鱼黑名单检查），再以 `rel="noopener noreferrer nofollow"` 新窗口打开。门卡列表（我的星愿）里的批次门卡同样按批次读取并显示（`GET /api/batch/pub?id=`）。
- **免责文案**（16 语言）：「附加图片与商品链接仅作展示，平台不对其真实性、可用性负责。」放在附加内容下方，并作为「费用与资金规则」第 7 条。
- **错误码**：`attMax`（> 20）、`attImg`（图片地址非法 / 不在平台存储）、`attLink`（商品链接格式错误 / 内网地址，预览接口的 SSRF 拒绝也返回此提示）、`att`（结构非法）。

## 3. 架构

```
 浏览器 ──(1 笔总额支付)──▶ 链 ──▶ 项目收款地址
   │                          ▲
   │ POST /api/batch/create   │ verifySolPay / verifyEvmPay
   ▼                          │
 ┌──────────────── server.js ───────────────┐
 │ 校验金额/内容 → 核验到账 → Batch.create  │
 └───────────────┬──────────────────────────┘
                 ▼
   batches.json（persist.js → D1 write-through）
   { meta.secret, batches{ shards[] }, codes{sha256 索引}, paid{}, alerts[] }
                 │  Batch.start(): 每 1 秒 tick()
                 ▼
   分片队列（每片 BATCH_SHARD=500 张）
   queued ─▶ running ─▶ done
      ▲          │失败：tries++，指数退避 min(900, 5·2^(n-1)) 秒
      └──────────┘ 超过 BATCH_MAX_TRIES(6) ⇒ failed + 告警日志
   running 超过租约（120 s）视为进程中断 ⇒ 重新排队（断点续传）
                 ▼
   领取码（HMAC 派生）→ codes 索引 → /claim → Gate.issue（门卡 g_…，gateId = b_<批次>）

   [后续项，未接入] IPFS：把祝福/批次清单固定到 IPFS 并在 memo 中记录 CID。
```

- **幂等**：领取码由 `HMAC-SHA256(secret, batchId:序号)` 确定性派生，分片重跑得到相同的码和相同的索引，不会重复发码；批次创建按支付签名幂等。
- **续传**：所有状态在 `data/batches.json`（并同步 D1）。重启后 `Batch.start()` 继续处理未完成分片；进度页可刷新、换设备（同钱包登录）继续看；浏览器 localStorage 仅作为本机备份列表。
- **失败告警**：`alerts`（环形 100 条）+ `console.error('[batch-alert] …')`，不含密钥、不含领取码。`GET /api/admin/batch`（`x-admin-key`）返回汇总、各批次状态与告警；`POST /api/admin/batch/retry {id}` 重新排队失败分片。

### 领取码：哈希 vs 可导出（取舍）

用户需要下载包含明文领取码的 CSV，所以不能只存不可逆哈希。方案：码 = HMAC(服务端密钥, 批次号:序号)，**库中只存 sha256 索引与状态**，需要导出时重新计算。
好处：数据库/D1/备份泄露不会泄露任何未领取的码；重试/重启导出结果完全一致。
代价：服务端密钥 `meta.secret`（或环境变量 `BATCH_SECRET`）一旦泄露，未领取的码可被推算——密钥不进 git、不进日志、不进 API。码为 100 bit（20 位 Crockford base32，格式 `XXXXX-XXXXX-XXXXX-XXXXX`），无法暴力枚举；另有限速。

### 领取与门卡

`#/claim/<code>`：先 `peek`（只返回祝福、门卡名、状态，不泄露所有者），登录后自动 `POST /api/batch/claim` 绑定：一码一领；同一账户重复打开为幂等（不重复发卡）；其他账户 → `used`。发卡走现有 `Gate.issue`（`source=batch`，永久，门卡名 = 批次门卡名称，`gateId = b_<批次号>`）。限速：claim 每 IP / 每账户 20 次 / 10 分钟，peek 每 IP 30 次 / 10 分钟（内存限流）。

### 上链（可选，用于验证）

只对**批次摘要**写一条 memo：`WTREE1|BG|<批次号>|<数量>|<Merkle 根前 32 位>`（Merkle 叶 = 各码索引的哈希）。该交易需要用户用**自己的钱包再签一笔并自付网络费用（gas）**，页面在选项处与进度页都明确提示；服务端 `POST /api/batch/anchor` 用 `verifyMemoTx` 校验（签名者 = 所有者、memo 完全一致）后才显示「已上链」，否则不会假装上链。不对每张卡单独上链。仅自有钱包支持。

### 进度页与 CSV

支付后自动进入；2 秒轮询（失败态 10 秒）；显示已生成/总数、分片、下次重试时间、已领取数。完成后下载 CSV：UTF-8 BOM，表头 `序号,领取码,领取链接,状态`，CRLF，状态为 已领取/未领取；仅批次所有者可下载（需登录令牌）。

## 4. API

| 接口 | 说明 |
| --- | --- |
| `GET /api/prices` | 公开：SOL/ETH/BNB 的 USD 价（中位数，缓存 60 秒，`stale` 标记） |

| `POST /api/batch/quote` `{count,coin,feeUsd}` | 登录：服务端锁价报价（返回报价令牌、应付币种数量、过期时间） |

| `POST /api/img` `{mime,data,att:true}` | 沿用上传接口：附加图片放宽到 ≤ 1200px / < 2MB，仍过类型 / 魔数 / NSFW 审核 |
| `POST /api/batch/create` | 登录：`{blessing,count,coin,valueUsd,redeemNote,feeUsd,gateName,optPublic,optAnchor,attachments?,quote, sig｜pay:true｜evm}` |
| `GET /api/batch/mine` / `GET /api/batch/<id>` / `GET /api/batch/<id>/csv` | 仅所有者 |
| `POST /api/batch/claim` `{code}` | 登录：领取并绑定 |
| `POST /api/batch/anchor` `{id,sig}` | 所有者：登记链上记录 |
| `GET /api/admin/batch`、`POST /api/admin/batch/retry` | 运维（`x-admin-key`） |

环境变量：`PRICE_MOCK=1`（测试：读 `data/prices-mock.json`，不访问网络）、`BATCH_QUOTE_TTL`（报价锁定秒数，默认 600）、`BATCH_SECRET`（可选，默认首次启动随机生成并持久化）、`BATCH_SHARD`（500）、`BATCH_MAX_TRIES`（6）、`BATCH_BACKOFF`（5 秒）、`ADS_MOCK_PAY=1`（测试：用 `data/ads-mock-pay.json` 模拟支付核验；`data/batch-mock-anchor.json` 模拟上链核验）。

## 5. 限制

- 数量 1–10000；每张平台费 ≥ 1 USD；卡片价值 ≥ 1 USD（仅记录）；币种仅 SOL/ETH/BNB。
- 价格依赖第三方公开行情源；全部不可用且无 15 分钟内真实报价时，创建会被拒绝（不会按兜底价格收费）。2% 滑点容差与 10 分钟锁价意味着平台可能多收/少收最多约 2%。
- EVM 账户可支付，但不支持「公开 1 张」「上链」；托管账户不支持「上链」，且 ≥ 20 USD 需自有钱包。
- 「专属门卡空间」= 以批次门卡名称签发的门卡（对接现有 gate 体系），没有新增独立空间功能。
- 平台不核实创建者的兑换说明，也不介入兑现纠纷；仅做自动长度/关键词/承诺字样过滤。
- 内存限流在多实例下各自独立。
- **IPFS 尚未接入**（仅为后续项）。
- **旧批次兼容**：改版前创建的批次没有价值/费用字段，显示时卡片价值按 0、兑换说明为空（领取页提示向创建者核实），其余功能（进度、CSV、领取）不变。

## 6. 未测试 / 风险

- 附加内容：测试环境没有外网（DNS 被劫持到保留地址），所以**真实商品页的 title / og:image 抓取与封面转存没有端到端跑通**（只验证了 SSRF 拒绝与失败降级）；上传审核在测试里用 NSFW 桩服务；附加图片没有逐张二次审核人工复核；附加内容不可修改，创建后发现违规只能由运维处理整个批次；R2 真实存储与 `R2_PUBLIC_URL` 302 路径未在本机验证。

- 真实链上支付（自有钱包 `signAndSend`、托管账户真实转账、EVM 的 ETH/BNB 真实转账）、真实上链 memo：测试全部使用 mock（`ADS_MOCK_PAY`、`PRICE_MOCK`），未做真实交易；EVM 核验链路在集成测试中只覆盖到币种/选项校验。
- 真实行情源（Coinbase/Binance/CoinGecko）在 Render 上的可达性与取中位数效果未做长期观测（Binance 在部分地区可能被限制，此时由其余源取中位数）。
